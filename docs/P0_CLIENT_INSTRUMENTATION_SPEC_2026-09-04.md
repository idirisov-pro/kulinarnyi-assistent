# P0: спецификация клиентского модуля событий

Дата: 2026-09-04

## Назначение

Модуль должен отделить регистрацию событий от продуктовой логики и от конкретного поставщика серверной аналитики.

## Основные свойства

- не должен ломать приложение при любой своей ошибке;
- должен создавать псевдонимный идентификатор установки;
- должен создавать новый идентификатор сеанса;
- должен сохранять источник перехода и UTM-метки в минимальном объёме;
- должен складывать события в локальную очередь;
- сетевой адрес приёмника должен задаваться отдельно;
- при отсутствии адреса приёмника события остаются только в локальной очереди;
- успешная отправка должна удалять только подтверждённые события;
- ошибки отправки не должны показываться пользователю как ошибки продукта;
- свободный текст отзыва не должен попадать в обычные аналитические события.

## Минимальный формат события

```json
{
  "event": "search_submitted",
  "occurred_at": "ISO-8601",
  "install_id": "псевдонимный идентификатор",
  "session_id": "идентификатор сеанса",
  "app_version": "версия приложения",
  "source": {
    "utm_source": null,
    "utm_medium": null,
    "utm_campaign": null
  },
  "properties": {}
}
```

Технические идентификаторы на английском допустимы в коде как устойчивые машинные имена. Пользовательский интерфейс остаётся русскоязычным.

## События первой версии

- `session_started`
- `ingredient_added`
- `ingredient_removed`
- `search_submitted`
- `results_shown`
- `zero_results`
- `recipe_opened`
- `cooking_started`
- `cooking_completed`
- `feedback_submitted`
- `session_returned`

## Ограничение

`feedback_submitted` можно фиксировать только после подтверждённого успешного сохранения отзыва в центральном хранилище. Пока центрального приёмника нет, это событие не должно генерироваться как успешное.
