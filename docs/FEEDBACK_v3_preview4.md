# Кулинарный ассистент — feedback → 3.0-preview.4

Дата фиксации: 2026-08-11

## Основание

Версия 3.0-preview.4 подготовлена как UX-correction после пользовательской обратной связи по предыдущей сборке.

## Обязательные исправления

1. **Поиск продуктов**
   - добавить видимую кнопку `×` для очистки;
   - после выбора найденного продукта автоматически очищать строку поиска.

2. **Количество порций**
   - заменить список 1–6 на бегунок и ручной числовой ввод;
   - диапазон текущего preview: 1–20;
   - синхронизировать оба элемента;
   - сохранять выбранное значение;
   - пересчитывать ингредиенты с бытовым округлением: граммы/мл без десятых, ложки с шагом ¼, штучные продукты без бессмысленных десятичных дробей.

3. **Сохранение параметров**
   - время, порции, сложность, режим подбора и категория не должны самопроизвольно сбрасываться при возврате к форме.

4. **Гибкий подбор**
   - режим «Можно добавить 1–2 продукта» должен действительно показывать такие рецепты;
   - если точного варианта нет, показывать до двух близких вариантов с конкретным объяснением, что нужно изменить: продукт, время или сложность;
   - не заставлять пользователя угадывать параметры рецепта последовательными возвратами к форме.

5. **Инструкции приготовления**
   - заменить расплывчатые указания вроде «нарежьте кусочками» на форму и приблизительный размер нарезки там, где это влияет на понятность и равномерность приготовления.

6. **Визуальный инкремент**
   - preview.4 должен заметно отличаться от preview.3: новая иерархия главного экрана, отдельные блоки этапов, крупный контрол порций, более явное разделение точных и близких вариантов.

## Не блокирует preview.4

- Фотографии/иллюстрации вариантов нарезки остаются в backlog как P2. Их следует добавлять только после проверки, что текстовых уточнений недостаточно.
- Таймер сохраняется, но прямо обозначается как необязательный.

## Критерии готовности

- `node quality-check.mjs` проходит без ошибок;
- значения порций 1, 5, 7, 12 и 20 корректно отображаются и масштабируют рецепт;
- пересчёт не показывает значения вида `575,3 г` или `1,3 ч. л.`;
- после выбора продукта поисковая строка очищается;
- выбранные 60 минут не возвращаются самопроизвольно к 45;
- flexible-mode показывает рецепт при 1–2 допустимых недостающих позициях;
- при отсутствии точного совпадения пользователь получает понятные близкие варианты вместо тупика.


## QA hotfix 2026-08-11

Контрольный сценарий в Chromium выявил два дефекта карточки рецепта:

- при отсутствии обязательного ингредиента кнопка «Начать готовить» оставалась активной; теперь она блокируется до добавления обязательных продуктов;
- при открытии близкого варианта, который превышает выбранный лимит времени, карточка теряла это ограничение; теперь предупреждение о времени сохраняется.

Service Worker cache обновлён отдельным hotfix-ключом, чтобы уже открывавшие preview.4 пользователи получили исправленный `app.js`, а не старую копию из cache-first.
